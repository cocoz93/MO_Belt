# Belt — 벨트스크롤 액션 (서버 검증용)

던전앤파이터 같은 벨트스크롤 액션의 **서버 쪽을 검증하려고** 만든 것이다.
재미있는 게임을 만드는 게 목적이 아니라, **4인이 한 방에 들어가서 때리고, 서버가 판정하고,
결과를 정산하는 흐름**이 실제로 도는지 보는 게 목적이다.

## 실행

`index.html` 을 브라우저로 열면 된다. 빌드 과정은 없다.

    방향키 / WASD   이동 (좌우 + 앞뒤 깊이)
    J 또는 스페이스  공격
    R               다시

그림이 안 뜨면 로컬 서버로 열어야 한다 (브라우저가 file:// 접근을 막는 경우).

## 파일

| 파일 | 하는 일 |
|---|---|
| `logic.js` | 좌표와 판정만. 브라우저 코드가 한 줄도 없다 — **이 파일이 나중에 그대로 C++ 서버가 된다** |
| `game.js` | 그리기와 입력. 서버를 붙여도 여기는 거의 안 바뀐다 |
| `index.html` | 화면 |

이렇게 가른 이유는 하나다. 서버가 정답을 계산하고 클라가 같은 계산을 미리 해보는 구조(클라 예측)로 가려면,
**양쪽이 똑같은 로직을 돌려야** 한다. 둘이 조금이라도 어긋나면 화면이 계속 튄다.

그래서 `logic.js` 에는 규칙이 있다.

- `Math.random` / `Date` / `document` / `window` 금지
- 시간은 초가 아니라 **틱**으로만 센다 (60Hz 고정)
- 실수는 C++ 로 옮길 때 반드시 `double` — `float` 를 쓰면 결과가 갈린다

### 검증용 스위치

헤드리스 브라우저에서는 `requestAnimationFrame` 이 돌지 않아 화면을 찍어도 첫 프레임만 나온다.
주소 뒤에 붙이면 미리 굴린 장면부터 그린다.

    ?sim=330&mx=1&atk=1     오른쪽으로 걸어가며 계속 휘두른 5.5초 뒤

## 에셋

**Tiny RPG Character Asset Pack 01 (Zerie)** — 무료판. 상업 사용 가능, **재배포 금지**.

재배포 금지라서 `assets/soldier/`, `assets/orc/` 는 저장소에 넣지 않는다(`.gitignore`).
클론한 뒤에는 직접 받아서 아래처럼 넣어야 돌아간다.

    assets/soldier/   Soldier_Idle.png  Soldier_Walk.png  Soldier_Attack01.png
                      Soldier_Hurt.png  Soldier_Death.png
    assets/orc/       Orc_Idle.png  Orc_Walk.png  Orc_Attack01.png
                      Orc_Hurt.png  Orc_Death.png

원본 팩의 `Characters(100x100 split)` 안에서 **`with shadows`** 쪽을 쓴다. 그림자가 있어야 바닥에 서 있어 보인다.

프레임은 가로로 이어 붙인 시트이고 한 칸이 100×100이다.
그 안에서 발이 닿는 자리는 y=59, 몸 가로 중심은 병사 49 / 오크 54다(실측값).
이 값이 어긋나면 캐릭터가 바닥에서 뜨거나 파묻힌다.
